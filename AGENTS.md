App-only, never re-exported — keeps every public page on one visual language without loading fonts from a third party.
- Tokens are CSS variables mapped through `@theme inline` in `theme.css` — keeps light/dark switching to a single `.dark` class.
- Interactive UI uses `@ui-sdk/react` + `@ui-sdk/core`, pinned to an exact beta (follow `node_modules/@ui-sdk/react/docs/llms.txt`): Dialog, AlertDialog, Drawer, Popover, Tabs, Switch and Select, styled only with the `twc-*`/`air-*` tokens. Selects go through `SelectControl`/`MultiSelectControl` (design system; native `<option>` children, `""` stays a real answer, never inside a `<label>`, whose click would reopen the list). A centred dialog needs `fixed inset-0 m-auto h-fit`. Questions before an action in the signed-in shells use `askConfirm` (`src/app/layout/confirm.ts`, one `ConfirmHost` per shell), never `window.confirm`. Page links stay links (`AreaTabs`) and text, date, checkbox and radio fields stay native — one behaviour on every page, with no third look.
- Form primitives use editorial and boxed variants from one shared family — keeps long applications expressive and compact forms consistent.
- Motion uses shared CSS timing tokens and reduced-motion fallbacks — keeps interactions consistent and accessible without adding a runtime dependency.
- Long membership forms compose reusable field, choice, notice, progress, section, and action primitives — keeps dense applications consistent and accessible.
- The canvas's three-star mark is the canonical logo (user decision, 2026-11-26; files in `docs/design-canvas/logos/`): `ConstellationLogo` draws it in its fixed color variants (ink, white, and each bundled neighborhood colour, the ink mark's alpha filled with that colour), each with a 128w lossless WebP downscale before the 168w PNG in its `srcset` (`logo-sources.ts`; a caller that sets its own width passes `sizes`), and `LOCKUP` is the wordmark lockup the site header uses — one geometry across every brand context.

- Decorative pointer motion uses the self-contained star `ImageTrail` (glittering sparkles) on public pages only (internal pages pass `trail={false}` to `AppPage`), disabled for touch and reduced motion — keeps the playful flourish accessible and attach-safe.

- Member accounts use Better Auth on the app's SQLite database (`src/server/auth.server.ts`, served at `/api/auth/*`): email + password with required verification, plus Google only when `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` are set (the button shows when `VITE_GOOGLE_AUTH === "true"`); ids are UUIDs. Membership status, catalogue number, member-since and roles are admin-only: members can never self-approve. An admin's direct approve/decline/undo-decline also updates the newest application (0004 behaviour). Approving (application review or direct member approve) prefills blank profile fields from the newest approved application as a private draft — never overwriting what she or an admin wrote, never copying phone/consents, never turning on `directory_visible` or `public_profile`; undo-decline does not prefill. A claim path fills the same blanks on `ownProfile` from an approved application only while the card is still private (not listed/public); admin approve passes `fromApproval` so a pending saved directory choice still gets the draft in that transaction. Migration `0019_application_draft.sql` stamps `application_draft_at` so a cleared field is never restored on the next read. Newly approved members with a still-private card see a one-time “You’re in” panel on `/account` with visibility next steps. A member deletes her own account from the Membership card on `/account` (`DeleteAccount.tsx`, a confirm step) through Better Auth's `user.deleteUser` (`POST /api/auth/delete-user`, Better Auth's own origin check, not `API_ROUTES`): a password account must send its password (a `hooks.before` refuses `PASSWORD_REQUIRED` otherwise; 5 attempts per IP per 10 minutes, so it is no password oracle), a Google-only one falls under Better Auth's fresh-session rule (signed in within a day), deletion tokens are refused, and `beforeDelete` (`src/server/account-delete.ts`) refuses admins, then deletes every application and imported `legacy_members` row with her user id or email (left unclaimed, it would approve the next account verified with that email, even after a decline) — declined applications go too, by choice: deletion is complete, and a returning account starts `pending`, which still needs an admin; the cascades take the rest, and `afterDelete` removes her `avatars` and `feed` upload folders.
- All data access is a TanStack Start server function in `src/features/*/fns.ts`; its handler lazy-imports the feature's `*.server.ts` and runs it through `serve()` (`src/server/context.server.ts`), whose domain code starts with `requireSession`/`requireMember`/`requireAdmin` from `src/server/guard.ts` — that is the security boundary (the old RLS), checked by `src/server/policy.test.ts`. The ten endpoints that take a body (`/api/images`, `/api/feed`, `/api/neighborhood-logos`, `/api/applications`, `/api/contact`, `/api/partnerships`, `/api/newsletter`, `/api/review`, `/api/spotlight`, `/api/forms/<slug>`) are server routes instead, so the size (Content-Length) and the caller are checked before the body is read; applications, contact messages, partnership inquiries and newsletter sign-ups are each limited to 5 per client IP per 10 minutes, member reviews and Spotlight answers to 10, custom-form answers to 10 per client IP per form, newsfeed posts to 10 per member per 10 minutes (their own `rateLimit()` from `src/server/request.ts`; `clientIp()`: `cf-connecting-ip`, then the first `x-forwarded-for`). The CSRF middleware covers them only because each is listed in `API_ROUTES` in `src/start.ts` — a new body-taking route must be added there, with a test. The browser never touches the database; client code imports only `fns.ts`, `postApi`, query/mutation modules and types.
- Code that needs a secret reads `process.env` only in server-only modules (`src/server/`, `*.server.ts`). Server env lives in the server's environment or the gitignored `.env.local`; tracked `.env` holds only `VITE_` values (`src/app/secrets.test.ts`). Every email goes through `sendEmail()` in `src/server/email.ts`, with links at `APP_URL`.
- The database is SQLite (`node:sqlite`) at `${DATA_DIR}/twc.db`; migrations are hand-written `db/migrations/NNNN_name.sql`, applied in order at startup via `PRAGMA user_version`. Never edit an applied migration; add the next one, with tests.
