# Agents

- All design-system source (theme CSS, components, helpers) lives in `src/design-system/` and is re-exported from `src/index.ts` — attach copies only that subtree, so nothing there may import from outside it. App code imports it only via `@/index`; ESLint `no-restricted-imports` enforces both directions.
- Showcase pages (`/colors`, `/typography`, `/components`) live in `src/routes/` and are the only routes on the `Shell` toolbar from `src/showcase/` (showcase-only helpers, excluded via `.dsignore`); they carry `noindex` and are disallowed in `public/robots.txt`. Live pages use `AppPage`, `AppNav` and `AppFooter` from `src/app/layout/AppLayout.tsx` — keeps the design-system toolbar off the live site and out of search, while the showcase stays preview-only and never re-exported.
- Public pages are the scrapbook site from the design canvas: the prop-less `AppNav` (About · Members · Gatherings · logo · Neighborhoods · FAQ · Sign in · Join us, a popover menu below lg) and lilac `AppFooter`, the `twc-*` classes in `src/app/twc.css` (the canvas's design system ported onto the `sb-*` tokens and self-hosted fonts, in `@layer components` so utilities win) and `Icon`/`Scallop`/`TwcRibbon` from `src/app/layout/twc.tsx`. Headlines are sentence-case Gilda Display, small blue text uses `sb-blue-ink` (`sb-blue` fails AA below 24px), and a `[BRACKETED]` fact on a board is never invented — the element is dropped instead. App-only, never re-exported — keeps every public page on one visual language without loading fonts from a third party.
- Tokens are CSS variables mapped through `@theme inline` in `theme.css` — keeps light/dark switching to a single `.dark` class.
- Form primitives use editorial and boxed variants from one shared family — keeps long applications expressive and compact forms consistent.
- Motion uses shared CSS timing tokens and reduced-motion fallbacks — keeps interactions consistent and accessible without adding a runtime dependency.
- Long membership forms compose reusable field, choice, notice, progress, section, and action primitives — keeps dense applications consistent and accessible.
- The uploaded constellation artwork is the canonical logo and `ConstellationLogo` owns its fixed color variants — preserves the original geometry across every brand context.
- Immersive image strips use the self-contained OGL circular gallery with a static reduced-motion fallback — preserves the editorial arc while remaining accessible and attach-safe.
- Decorative pointer motion uses the self-contained flower `ImageTrail`, disabled for touch and reduced motion — keeps the playful flourish accessible and attach-safe.
- Motion that starts on its own either stops within 5 s (`CurvedLoop`) or has a pause control (`Ribbon`) — WCAG 2.2.2, even when the motion is decorative and `aria-hidden`.
- Catalogue cards open details through `MemberCard`'s `onOpen` and one `MemberDialog` (a native modal `<dialog>`) per page; members without a portrait get the card's initials mat, never a stand-in photo — keeps cards honest and the dialog accessible without a dialog library.
- Demo member profiles live in `src/showcase/demo-members.ts` (with their portraits in `src/showcase/assets/`), outside the design system and the public barrel; only `MemberProfile` is type-exported with `MemberCard` — keeps the reusable API typed without pulling sample portraits into consumer bundles.
- Design rules (tokens, type, the `--hood` inline-style exception) live in `DESIGN.md` at the repo root.
- Member accounts use Better Auth on the app's SQLite database (`src/server/auth.server.ts`, served at `/api/auth/*`): email + password with required verification, plus Google only when `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` are set (the button shows when `VITE_GOOGLE_AUTH === "true"`); ids are UUIDs. Membership status, catalogue number, member-since and roles are admin-only: members can never self-approve. An admin's direct approve/decline also updates the newest application (0004 behaviour).
- All data access is a TanStack Start server function in `src/features/*/fns.ts`; its handler lazy-imports the feature's `*.server.ts` and runs it through `serve()` (`src/server/context.server.ts`), whose domain code starts with `requireSession`/`requireMember`/`requireAdmin` from `src/server/guard.ts` — that is the security boundary (the old RLS), checked by `src/server/policy.test.ts`. The five endpoints that take a body (`/api/images`, `/api/neighborhood-logos`, `/api/applications`, `/api/contact`, `/api/partnerships`) are server routes instead, so the size (Content-Length) and the caller are checked before the body is read; applications, contact messages and partnership inquiries are each limited to 5 per client IP per 10 minutes (their own `rateLimit()` from `src/server/request.ts`; `clientIp()`: `cf-connecting-ip`, then the first `x-forwarded-for`). The CSRF middleware covers them only because each is listed in `API_ROUTES` in `src/start.ts` — a new body-taking route must be added there, with a test. The browser never touches the database; client code imports only `fns.ts`, `postApi`, query/mutation modules and types.
- Code that needs a secret reads `process.env` only in server-only modules (`src/server/`, `*.server.ts`). Server env lives in the server's environment or the gitignored `.env.local`; tracked `.env` holds only `VITE_` values (`src/app/secrets.test.ts`). Every email goes through `sendEmail()` in `src/server/email.ts`, with links at `APP_URL`.
- The database is SQLite (`node:sqlite`) at `${DATA_DIR}/twc.db`; migrations are hand-written `db/migrations/NNNN_name.sql`, applied in order at startup via `PRAGMA user_version`. Never edit an applied migration; add the next one, with tests.
- Uploads live under `${DATA_DIR}/uploads/` and are served only by `/media/*` (`src/server/media.ts`): magic-byte checked on upload, visibility from the old storage rules, 404 for anything not visible or outside a bucket.
- Live pages put their content in one `<main id="main" tabIndex={-1}>` after `AppNav` (`AppPage` adds the skip link), and the root's `useRouteFocus` focuses its `h1` after each navigation — keeps landmarks and route announcements consistent for screen readers.
- Internal (signed-in) pages — `/account` and `/admin`, and any future page under `_authenticated` — use the app shell instead of `AppNav`/`AppFooter`: `AppShell` + `TopBar` (`src/app/layout/AppShell.tsx`: sidebar, a modal `<dialog>` drawer below lg, sticky top bar), the card vocabulary in `app-ui.tsx` (`Card`, `Row`, `Chip`, `Toggle`, `EditButton`, `InlineError`), the control classes in `app-classes.ts` and the icons in `icons.tsx`, all on the `app-*` tokens. Public pages never use it. The sidebar's groups (Collective, My Account, Admin for admins only — UX only, the guards decide) link `page#card`; a card on the current page is an in-page anchor with `aria-current` while in view. Each page passes its `page` and `admin` and keeps `AppPage`'s skip link and one `<main id="main">`; its `h1` is the member's name on `/account` and the top bar title on `/admin`. On `/account` cards edit into one draft that Save sends as only the changed fields — keeps every signed-in screen one consistent, accessible settings app.
- Contrast is tested, not eyeballed: `src/app/contrast.test.tsx` checks token pairs parsed from `theme.css` (including every app-shell pair), so a token or text-colour change that drops below WCAG AA fails the suite.
- `src/start.ts` owns the request middleware: security headers (`src/app/security-headers.ts`: an enforced, same-origin-only CSP from `contentSecurityPolicy()` — `connect-src 'self'`, `img-src 'self' data: blob:`, `frame-ancestors 'self'`, `object-src 'none'`; a new external origin goes there, with a test) plus Start's CSRF check restated, because a start instance replaces Start's default middleware — never drop `csrfMiddleware`. `server.mjs` puts the same headers on static files.
- Public reads of member data return only what `publicProfiles()` returns (approved + directory-visible + public profile): `/members/:slug` (name + catalogue number; the number alone resolves, a stale name redirects) is a 404 for anyone else signed out, and approved members also see directory-visible members there under `noindex`. `/sitemap.xml` is a server route (`src/server/sitemap.ts`) listing `INDEXED` from `src/app/seo.ts`, active neighborhoods and public member pages — keeps private members out of search the moment they turn their page off.
- Contact messages and partnership inquiries are stored in `inbox_messages` (migration 0002) and then emailed to every admin (`receiveMessage` in `src/features/contact/contact.server.ts`): consent is required, a filled `honeypot` gets the same success with nothing stored or sent, and the `/admin` Inbox card lists `new` ones for archiving (`requireAdmin`) — keeps every message even when mail fails.
